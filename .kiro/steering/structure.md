# Structure

```
/
├─ .kiro/
│  ├─ steering/        product.md, tech.md, structure.md
│  ├─ specs/           generated by the Kiro spec workflow
│  ├─ hooks/           agent hooks

├─ index.html
├─ src/
│  ├─ main.ts          app entry: boot, page layout, screen router

│  │  ├─ controller.ts dispatch loop, session/NO CARRIER timers, view model, visibility
│  │  ├─ effects.ts    runs core effects through platform and audio wrappers
│  │  └─ input.ts      keydown / click / prompt submit → core events
│  ├─ core/            pure logic — no DOM, no browser APIs, no timers, `now` passed in
│  │  ├─ config.ts     fee rate, durations, presets, aliases, timing constants
│  │  ├─ fee.ts
│  │  ├─ time.ts       elapsed / remaining, MM:SS format and parse
│  │  ├─ url.ts        custom URL validation and normalization
│  │  ├─ session.ts    state machine: IDLE → DIALING → SELECT_DEST → SELECT_DURATION → CONNECTED → ENDED

│  │  ├─ record.ts     session record / active session types, serialize and parse
│  │  └─ history.ts    aggregate receipts into today / this-week totals, 1000-record cap
│  ├─ screens/         one file per screen; each exports render(root, state, view)
│  │  ├─ view.ts       ViewModel / Handlers types and DOM helpers (mount by screen key, slots)

│  │  ├─ dial.ts

│  │  ├─ nocarrier.ts
│  │  └─ receipt.ts
│  ├─ audio/

│  │  ├─ storage.ts
│  │  ├─ notify.ts
```

## Rules
- `src/core` must not import from `app`, `screens`, `audio`, or `platform`.
- Anything that touches the DOM, timers (`setTimeout`, `setInterval`, `requestAnimationFrame`), browser events, or `Date.now()` lives outside `src/core` — in `src/app`, `src/screens`, `src/audio`, or `src/platform`.
- Screens never call browser APIs directly; they go through `src/platform`. Screens only build DOM from the state and view model they are given.
- Time is always passed in as a `now` parameter to core functions.
- Keep each file under about 200 lines; split when it grows.
- Never add `/.kiro` or any of its subfolders to `.gitignore` (submission requirement).
- New tests go next to their kind: pure-logic properties in `tests/property`, parser and edge cases in `tests/unit`.
